# Model: SimulationEvent

Events are generated deterministically by `eventGenerator.ts` based on building state thresholds and resident traits. They are NOT generated by the LLM.

## TypeScript Interface

```typescript
interface SimulationEvent {
  id: string;
  type: EventType;
  sourceId: string;           // Resident ID who triggered it (or "building")
  targetId?: string;          // Resident ID who is targeted (if applicable)
  severity: number;           // 0–100 — scales emotional impact
  timestamp: number;          // tick when generated
  metadata: Record<string, unknown>;  // Type-specific extra data
}

type EventType =
  // Building infrastructure
  | "elevator_broken"
  | "water_leak"
  | "power_outage"
  | "cleanliness_complaint"

  // Social / interpersonal
  | "noise_complaint"
  | "parking_dispute"
  | "pet_complaint"
  | "renovation_noise"
  | "public_accusation"
  | "rumor_spread"
  | "alliance_formed"
  | "alliance_broken"

  // Player-triggered
  | "player_promise_made"
  | "player_promise_broken"    // Auto-generated if promise not resolved in time
  | "player_muted_resident"
  | "player_warned_resident"
  | "player_public_message"

  // Game pressure
  | "no_confidence_signal"     // Resident explicitly expresses opposition to player
  | "support_signal"           // Resident publicly supports player
  | "resident_left_group";     // Resident rage-quit the WhatsApp group
```

## Event Generation Rules

Events are chosen based on probability weights that scale with state:

```
noiseLevel > 60   → noise_complaint probability += 40%
chaosLevel > 50   → public_accusation probability += 20%
gossip resident anger > 70 → rumor_spread probability += 60%
broken promise exists → player_promise_broken guaranteed after N ticks
resident trust < 20 → no_confidence_signal probability += 30%
```

Events select a `sourceId` resident weighted by:
- How relevant their sensitivities are to the event type
- Current anger level
- Social activity (gossip_tendency trait)
